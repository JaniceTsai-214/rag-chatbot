# 01 需求

← 回到 [主檔](00-main.md)

## 1. 背景

以自有文件為知識來源的**個人用**問答機器人。第一階段在筆電本機驗證回答品質；第二階段接上 LINE 官方帳號自動回覆訊息。

## 2. 第一階段功能需求

| 編號 | 需求 | 說明 / 驗收重點 |
|---|---|---|
| R-01 | 聊天介面 | 瀏覽器開啟本機網頁，輸入問題、看到回答；支援多個對話 |
| R-02 | 匯入文件 | 支援 PDF、Word（.docx）、Markdown（.md）、FAQ（.csv / .xlsx） |
| R-03 | 重新匯入 | 同一檔案修改後重新匯入，舊內容被取代，不重複 |
| R-04 | 刪除文件 | 可從知識庫移除某份文件 |
| R-05 | RAG 回答 | 依問題檢索相關段落，交給本機 LLM 依段落回答 |
| R-06 | 顯示依據 | 每則回答附上參考段落：檔名、頁碼/標題、原文、相似度分數 |
| R-07 | 拒答機制 | 檢索不到夠相關的段落時，回覆固定拒答文字，不讓模型自由發揮 |
| R-08 | 對話紀錄 | 所有問答保存在本機，重開程式後仍可查看 |
| R-09 | Prompt 管理 | 在介面上編輯 System Prompt，每次儲存成新版本，可切換版本 |
| R-10 | 重新測試 | 對某則歷史問題，用目前（或指定）Prompt 版本重跑並並排比較 |
| R-11 | 批次評估 | 用一份測試題集整批重跑，輸出報告（回答、依據、是否命中預期來源） |

## 3. 非功能需求

| 編號 | 需求 |
|---|---|
| N-01 | 完全本機運作：文件、向量、對話紀錄、LLM 都在筆電上 |
| N-02 | 回答時間目標 **≤ 60 秒**（3B 模型，本筆電） |
| N-03 | 介面語言：繁體中文 |
| N-04 | 參數（模型、top_k、門檻、拒答文字等）集中在 `config.toml` |
| N-05 | 核心邏輯可被第二階段（LINE Webhook）直接重用 |

## 4. 範圍外（第一階段不做）

- 使用者登入、多人權限
- 掃描版 PDF 的 OCR（只處理含文字層的 PDF）
- 圖片、表格的精細解析（表格以純文字擷取）
- LINE 串接（第二階段）

## 5. 需求細節

| 項目 | 內容 |
|---|---|
| 文件規模 | < 100 份、< 2,000 頁 |
| 文件語言 | 繁體中文為主，夾雜英文 |
| PDF 類型 | 含文字層（非掃描） |
| FAQ 格式 | CSV / Excel，欄位 `question`、`answer`（可選 `category`） |
| 多輪對話 | 追問時把最近 2 輪對話與新問題合併後再檢索 |
| 拒答文字 | 「目前的資料中找不到相關資訊。」 |
| 回答風格 | 簡潔、繁體中文、條列優先，約 300 字以內 |
| 內容分級 | 不區分；第二階段再討論哪些內容不經 LINE 回覆 |
