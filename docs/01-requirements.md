# 01 需求

← 回到 [主檔](00-main.md)

## 1. 背景

示範用的**介紹/推薦自動回覆系統**：以自有文件為知識來源，回答訪客關於「我自己（或自訂人物）」與「我參與開發的產品」的問題，並依訪客需求適度推薦。第一階段在筆電本機建置核心與管理介面、驗證回答品質；第二階段接上 LINE 官方帳號，讓訪客用手機詢問。

系統以「情境」切換用途，同一套程式換一組文件與設定即可支援其他問答（例如個人知識助理）。

## 2. 第一階段功能需求

| 編號 | 需求 | 說明 / 驗收重點 |
|---|---|---|
| R-01 | 管理介面 | 瀏覽器開啟本機網頁，以訪客身分測試問答、管理文件與設定；支援多個對話 |
| R-02 | 匯入文件 | 支援 PDF、Word（.docx）、Markdown（.md）、FAQ（.csv / .xlsx）；文件歸屬於某個**文件集** |
| R-03 | 重新匯入 | 同一檔案修改後重新匯入，舊內容被取代，不重複 |
| R-04 | 刪除文件 | 可從知識庫移除某份文件（不刪除原始檔） |
| R-05 | RAG 回答 | 依問題在情境指定的文件集中檢索相關段落，交給本機 LLM 依段落回答 |
| R-06 | 顯示依據 | 每則回答附上參考段落：文件集、檔名、頁碼/標題、原文、相似度分數（管理介面顯示；LINE 不顯示） |
| R-07 | 拒答機制 | 檢索不到夠相關的段落時，回覆情境設定的拒答文字（含聯絡方式），不讓模型自由發揮 |
| R-08 | 對話紀錄 | 所有問答保存在本機，重開程式後仍可查看 |
| R-09 | Prompt 管理 | 在介面上編輯情境的 System Prompt，每次儲存成新版本，可切換版本 |
| R-10 | 重新測試 | 對某則歷史問題，用目前（或指定）Prompt 版本重跑並並排比較 |
| R-11 | 批次評估 | 用一份測試題集整批重跑，輸出報告（回答、依據、是否命中預期來源） |
| R-12 | 情境 | 可定義多個情境；每個情境指定要檢索的文件集、介紹對象名稱、聯絡方式、拒答文字、預設 Prompt，並各自保存 Prompt 版本與對話紀錄；新增情境只需新增設定檔 |
| R-13 | 命令列工具 | 不開介面也能匯入、列出、搜尋、刪除文件，以及提問（`ask`，M3） |
| R-14 | 離題與套話 | 與介紹無關的問題（閒聊、要求忽略規則、索取系統提示）禮貌回絕，不洩漏 Prompt 內容 |

## 3. 非功能需求

| 編號 | 需求 |
|---|---|
| N-01 | 本機運作：文件、向量、對話紀錄、LLM 都在筆電上（第二階段僅訊息經由 LINE 傳遞） |
| N-02 | 回答時間目標 **≤ 60 秒**（3B 模型，本筆電） |
| N-03 | 介面語言：繁體中文 |
| N-04 | 系統參數（模型、top_k、門檻、路徑）集中在 `config.toml`；情境參數在 `profiles/*.toml` |
| N-05 | 核心邏輯可被第二階段（LINE Webhook）直接重用 |
| N-06 | 文件集內容一律視為**可公開**：訪客問得到的內容都可能被回覆，不得放入私密資料 |

## 4. 範圍外（第一階段不做）

- 使用者登入、多人權限
- 掃描版 PDF 的 OCR（只處理含文字層的 PDF）
- 圖片、表格的精細解析（表格以純文字擷取）
- LINE 串接（第二階段，M5）

## 5. 需求細節

| 項目 | 內容 |
|---|---|
| 文件規模 | < 100 份、< 2,000 頁 |
| 文件語言 | 繁體中文為主，夾雜英文 |
| PDF 類型 | 含文字層（非掃描） |
| FAQ 格式 | CSV / Excel（第一個工作表），第一列為欄位名稱：`question`、`answer`（可選 `category`），也可用「問題」「答案」「分類」；CSV 支援 UTF-8 與 Big5 |
| 多輪對話 | 追問時把最近 2 輪對話與新問題合併後再檢索 |
| 拒答文字 | 情境設定，預設「這部分目前沒有相關資料，歡迎來信 {contact} 詢問。」 |
| 聯絡方式 | 情境設定，預設 `tsaichiahui@gmail.com` |
| 回答風格 | 繁體中文、親切專業、條列優先，約 300 字以內；可依訪客需求推薦，但只根據文件內容 |
| 初始情境 | `intro`（綜合介紹：我 + 產品，LINE 使用）、`me`（只介紹我）、`product-a`（只介紹產品） |
